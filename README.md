# 服务器状态卡

把主机状态画成一张图，底下带一句 AI 点评。

**作者：FULL**　·　Bilibili：[@白木不华](https://space.bilibili.com/)　·　MIT 开源

完全开源，随便改随便分发，不用找我报备。

## 一、指令

| 指令 | 别名 | 作用 | 一般耗时 |
| --- | --- | --- | --- |
| `/状态卡` | `/服务器状态卡` `/出状态卡` | 直接出一张卡 | 有代码风格时 0.2s 上下；走样式 JSON + AI 点评约 3~8s |
| `/状态卡主题 <描述>` | `/生成卡片风格` `/卡片风格` | 让模型单独生成一套样式 JSON | 10~20s |
| `/状态卡重做风格 [要求]` | `/重做卡片风格` `/随机风格` `/换个风格` | 随机抽一个视觉方向，让模型重写代码画一张 | 第一版就过约 10s，两版都重试最多 20s 出头 |
| `/状态卡自由生成 [要求]` | `/自由生成` `/代码生成卡片` `/状态卡代码` | 按你写的要求，让模型直接写代码画一张 | 同上 |
| `/状态卡HTML生成 [要求]` | `/HTML生成` `/网页状态卡` `/状态卡网页生成` `/网页生成` | 让模型写一整页 HTML，Edge 截成图，存成 `HTML_` 开头的模板 | 同上 |
| `/状态卡 随机 [关键词]` | `/服务器状态卡 随机 霓虹` | 从收藏夹里抽一个名字带这个关键词的模板出图，不带关键词就整个收藏夹随机 | 和上面出图一样快 |
| `/状态卡 收藏夹` | `/状态卡 收藏` | 看看收藏夹里有几个模板、都叫什么 | 立刻 |

几个说明：

- `/状态卡主题` 生成的是 **JSON 样式**，只能调整已有板块的配色、字号、顺序。
- `/状态卡重做风格` 和 `/状态卡自由生成` 生成的是 **PIL 绘图代码**，排版、背景、构图全都能改，不受字段限制。
- `/状态卡HTML生成` 生成的是 **HTML 模板**，写的是网页，走浏览器截图，CSS 那些效果都能用。
- 跑通的模板会自动存成 `styles/PIL_<名字>_<月日>_<时分>.py`，网页那份是 `HTML_` 开头。
- 生成完想固定下来，就去配置里把「代码风格文件」填上那个文件名（或者填 `random` 随机抽）。
- `/状态卡 随机 霓虹` 只在收藏夹里找，收藏夹没有才回头去 `styles/` 根目录找；两边都没有会告诉你现在都有哪些。
- 关键词是文件名模糊匹配，大小写不管，`随机 赛博` 和 `随机 cyber` 各算各的。
- 收藏夹认 `.py` `.json` `.html` 三种，`.html` 走浏览器渲染，另外两种按各自的路子来。

### 尺寸怎么写

指令后面能直接带尺寸，放前面放后面都行：

| 写法 | 效果 |
| --- | --- |
| `/状态卡 9:16` | 竖版 1080×1920 |
| `/状态卡 1080x1920` | 就要这个尺寸 |
| `/状态卡 竖版` | 竖版 |
| `/状态卡 4:3` | 横版 1600×1200 |
| `/状态卡自由生成 9:16 赛博风` | 尺寸和风格一起给 |

认的比例有 `9:16` `16:9` `3:4` `4:3` `2:3` `1:1` `4:5`，另外认 `竖版` `横版` `方形`。写了具体尺寸就按具体的来，没写看配置里的「代码绘图的画布」，两边都空就让模型自己挑一个。

配置里除了写死尺寸，还能写四种模式，每轮自己变：

| 填什么 | 效果 |
| --- | --- |
| `1080x1920` / `9:16` / `竖版` | 固定这个尺寸，每轮都一样 |
| `随机内置` | 从内置六档里抽一个：1600×1200、1200×1800、1080×1920、1440×1440、1920×1080、1200×1600 |
| `随机池` | 从「随机画布候选」那栏自己写的池子里抽，留空还是内置六档 |
| `奇葩比例` | 从 21:9、1:3、17:5、5:2 这些里摇一个，长边随机，再抖几十像素，出来基本没有正常版面 |

随机模式是在第①步之前就摇定的，摇完当成硬尺寸喂给规划，所以一轮里不会中途换。

内置版式不是按比例排的，出完图会等比塞进目标尺寸，多出来的用底色补，不会拉变形；只有模型现写的代码模板才是真正按竖版排满的。

### 指令后面能跟多个词吗

能，以前不能——AstrBot 只把第一个词塞进指令函数的参数，`/状态卡自由生成 奇葩比例 某个人物风格 图片全用上` 到插件手里只剩「奇葩比例」，后面的风格词、`图片全用上` 全丢了，画图那步根本没见过它们。现在统一改用 `event.message_str` 抠整串，四个指令（`/状态卡`、`/状态卡自由生成`、`/状态卡HTML生成`、`/状态卡重做风格`）都吃得到整句。

顺带：指令里写 `奇葩比例` `随机内置` 也会当场换画布，写完这个词会从风格描述里去掉，不会污染风格名。

### 点评一定会出现吗

不一定——③只负责画图，点评是它拿到的一个字符串参数 `comment`，得它自己在代码里写上去。模型有时只顾排版，把这件事忘了，图就干干净净没有吐槽。

所以现在三重保险：①规划时要求最底下一块留给点评（占 10%~18% 的横条）；③的提示词里把「comment 必须画出来，还要标 who」写成硬性要求；万一还是漏了，出图后会检查代码到底有没有用过 `comment`，没用就自动在底部补一条半透明黑条，日志里会写「代码没把点评画进去，已在底部自动补一条」。

自动补只对自由生成生效，收藏夹里那些老风格文件不会被强行加黑条。

### 一次生成要调几次模型

自由生成、重做风格这两条指令，一轮下来最多四次调用：

| 步 | 干什么 | 能不能省 | 一般耗时 |
| --- | --- | --- | --- |
| ① 规划打底稿 | 定尺寸、挑字段、起中文名，顺手交一段能跑的代码骨架 | 不能，`flow_base` 只决定要不要骨架 | 5~8s |
| ② 挑图 | 按文件名从素材目录挑图，说清放哪、多大、怎么裁 | 能，`flow_pick` 关掉就跳过 | 2~5s |
| ③ 画图 | 在①给的骨架上填内容，崩了回喂报错重写 | 不能，`flow_retry` 管重试几版 | 30~120s |
| ④ 点评 | 写底部那句吐槽 | 能，`comment_mode` 设 `off` | 和③同时跑 |

**①为什么要出代码骨架**：一直是从零写整段代码，模型每次都要自己发明渐变、圆角、进度条这些函数，写漏一个就整版崩（遇到过 `NameError: name '_grad' is not defined`）。现在第①步就把它钉死：画布多大、分几块、每块放哪、用哪些辅助函数，全在骨架里定好，第③步只填空。

骨架要是没交上来，或者交了跑不通，插件会退回内置的那份工具集继续跑，不会整轮失败。

**③崩了怎么办**：把报错原样回喂给模型再写一版，`flow_retry` 默认 2 版、最多 4 版。版数越多总耗时越长，同一次生成里④点评只算一次，不重复调。

四个环节能各配各的模型，见下面「每个环节用哪个模型」。


## 二、配置

### 素材与随机

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `asset_dir` | 空 | 素材文件夹。留空只用插件目录下的 `assets/` |
| `rand_mood_list` | 空 | 随机方向池，一行一个。留空用内置 20 条；只想固定一个方向就写一行 |
| `rand_canvas_list` | 空 | 随机画布候选，逗号分隔，`1080x1920` 和 `9:16` 都认。画布填 `随机池` 时用这个，留空用内置六档 |

素材文件夹可以放子文件夹，层数不限：

```
素材/
├── 人物甲/
│   ├── 图一.jpg
│   └── 图二.png
└── 作品乙/
    └── 立绘/
        └── 立绘_角色_1.png
```

生成时会把整份清单（相对路径 + 分辨率 + 文件大小）交给挑图那一步，让它按名字挑，不需要视觉模型。挑中的会写进绘图提示词，连放哪、多大、怎么裁一起说清楚。它自己编出来的文件名会被丢掉。

它挑的时候守两条：你点名要某张贴纸就只挑那张，不乱抓同文件夹的一堆；一张能撑起整卡就只挑一张，最多三张。一张都不合适就交空数组，拿纯图形画。

### 调用流程

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `flow_base` | 开 | ①规划那步要不要同时交代码骨架。关掉只出 JSON，省一点，但③更容易飘 |
| `flow_pick` | 开 | ②挑图这步开不开。关掉整轮少一次调用，这轮一张素材都不画 |
| `flow_retry` | 2 | ③画图崩了重写几版，最多 4 |
| `flow_prelude` | 空 | 骨架工具函数，每版代码跑之前先执行。留空用内置那份 |

内置的骨架工具，模型直接调，不用自己造：

| 函数 | 作用 |
| --- | --- |
| `_grad(img, box, c1, c2, horizontal=False)` | 往画布上贴一块渐变 |
| `_rr(d, box, r, fill=, outline=, width=)` | 圆角矩形 |
| `_txt(d, xy, 文字, size=, color=, bold=, anchor=)` | 写字，返回文字宽度 |
| `_bar(d, box, 百分比, 前景色, bg=)` | 进度条 |
| `_fit(img, 素材图, box, pos="center")` | 等比塞进框里，不拉变形 |
| `_hex("#ff8800")` | 十六进制转 (r,g,b,a) |

想加自己的工具就往 `flow_prelude` 里写，写进去的每版都会先执行一遍。

## 三、风格是怎么工作的

有三种，越往下越自由：

**1. 样式 JSON**（`styles/*.json`）
限定在现有六个板块里调：`header` `kpi` `chart` `config` `disk` `comment`。能改顺序、间距、字号、配色、背景光斑。自带 `default` `midnight` `neon` `forest` `cyber` 五套。

**2. 随机方向**（`/状态卡重做风格`）
内置 20 个视觉方向：极简黑白海报、赛博朋克霓虹、复古报纸、蒸汽波、科幻 HUD、工业暗红、日式侘寂、像素复古、玻璃拟态、杂志封面、工程蓝图、故障艺术、粗野主义、数据可视化海报、终端窗口、暗黑哥特、糖果色、水彩纸质、军事简报、太空站。每次随机抽一个，让模型按这个方向重写代码。

**3. 自由代码**（`/状态卡自由生成`）
你自己描述，想要什么给什么。

**3.5 自由网页**（`/状态卡HTML生成`）
一样是你说，但这次模型写的是 HTML，CSS 随便用，截出来就是图。

**4. 收藏夹**（`styles/_favorites/`）
插件自己生成的风格会随存档轮换被清掉，自己觉得好的就往 `styles/_favorites/` 里丢一份，`.py` 绘图代码、`.json` 样式都认。放进去的文件插件只读不写、不参与备份轮换、也不会被清掉，想攒多少攒多少。

```
styles/_favorites/
├── 暗紫霓虹.py               直接整份拷进来的绘图代码
└── 赛博紫.json               一份样式 JSON
```

丢好之后 `/状态卡 随机 霓虹` 就会抽到它，没关键词就是整个收藏夹里随机。

代码执行的限制：`import` 只放行 PIL / math / time / random / colorsys / itertools / datetime；禁 `while True`；禁 `open` `eval` `exec` 和双下划线属性；builtins 换白名单，拿不到 `os` `sys` `socket`。挡得住手滑，别拿它跑陌生来源的代码。

## 四、两个渲染器

配置里「出图渲染器」二选一，同一份样式 JSON 两边都认。

| 渲染器 | 怎么画的 | 一般耗时 | 适合 |
| --- | --- | --- | --- |
| `pil` | 直接往画布上画，坐标全靠算 | 0.1~0.7s | 版式固定、要快、要精确到像素 |
| `html` | 拼 HTML，Edge 无头截图 | 1~2s | 排版复杂、字多、想要 CSS 那些效果 |

**文件名前缀最优先**，格式次之，配置垫底。文件名只看 basename，不区分大小写：

| 文件名 | 用哪个渲染器 |
| --- | --- |
| `HTML_霓虹.py` | 浏览器。`.py` 里放一个 `TEMPLATE` 字符串就行 |
| `PIL_霓虹.py` | 代码绘图，就是平时那种 `draw()` 写法 |
| `霓虹.html` | 浏览器 |
| `霓虹.py`（没前缀） | 代码绘图，老文件全走这条，不用改 |
| `霓虹.json` | 看配置里的 `renderer` |
| `HTML_霓虹.html` | 浏览器，前后缀一致不打架 |

也就是说想让一份模板走浏览器，不用管配置怎么选，名字前面挂个 `HTML_` 就行。`HTML_` 开头的 `.py` 里没有 `TEMPLATE` 字符串时会退回配置，不会闷声出个空图。配置文件里 `code_file` 填的那份同样认前缀。代码绘图是 PIL 语法，选了 HTML 也会自动退回 PIL，不会跑到一半崩。

生成出来的模板会自己带上前缀，不用手动改：`/状态卡 重做风格`、`/状态卡自由生成` 存成 `PIL_风格名_月日_时分.py`，`/状态卡HTML生成` 存成 `HTML_风格名_月日_时分.py`。

HTML 用的是系统里的 Edge 或 Chrome，两个都没有才会报错。Windows 自带的 Edge 就够。

### 用 .py 写 HTML 模板

`.html` 文件不好塞进收藏夹的时候（比如想连注释一起存），可以写成 `.py`，文件名加 `HTML_` 前缀，里面放一个 `TEMPLATE` 字符串：

```python
# styles/_favorites/HTML_霓虹.py
TEMPLATE = """
<!doctype html>
<html><body style="margin:0;background:#0b1020;color:#e8eef6">
  <div style="padding:60px;font-size:52px">{{ host }}</div>
  <div style="padding:0 60px;font-size:30px">CPU {{ cpu }}%</div>
  {% for m in moods %}
  <div style="padding:0 60px">{{ m.name }} {{ m.val }} {{ m.word }}</div>
  {% endfor %}
</body></html>
"""
```

`TEMPLATE` / `HTML` / `TPL` 随便哪个名字都能认，只执行读到字符串那一步，函数和导入不会被调用。模板变量跟上面那张表一样。写错的变量名不会报错，只会渲染成空。

### 自定义 HTML 模板

`styles/` 或者 `styles/_favorites/` 里丢 `.html` 文件，Jinja2 语法，页面尺寸 1600×1200。能用的变量：

| 变量 | 内容 |
| --- | --- |
| `W` `H` | 画布宽高，1600 / 1200 |
| `host` `up` `now` | 主机名、已运行时长、当前时间 |
| `cpu` `mem_pct` `mem_used` `mem_total` `proc_total` | 三指标，都已经是字符串 |
| `bars` | 进程柱状图，每项 `{name, mb, pct}` |
| `cfg` | 硬件配置，`cpu cores threads gpu os ram disk` |
| `disks` | 磁盘，每项 `{tag, used, total, pct, color}` |
| `moods` | 三个状态值，每项 `{name, val, word, color}` |
| `comment` `who` | 点评文字和点评者名字 |
| `blocks` | 板块顺序列表 |
| `c` | 配色，`bg_top bg_bottom title subtitle label text sub faint cpu mem proc cfg disk_c disk_d comment bar_top bar_bottom split card hair`，全是 CSS 颜色字符串 |
| `fs` | 字号，`title subtitle kpi section comment` 等，取出来是数字 |
| `glow_css` `vignette` `grid_step` `grid_alpha` | 背景光斑、暗角、网格 |
| `margin_x` `top_margin` `block_gap` `chart_h` | 边距和块间距 |
| `d` | 原始数据，要什么自己取 |

写个最小的能跑的：

```html
<!doctype html><html><head><meta charset="utf-8"><style>
html,body{width:{{W}}px;height:{{H}}px;overflow:hidden;
  font-family:"HarmonyOS Sans SC",sans-serif;color:#fff;
  background:linear-gradient(135deg,#05070d,#101a33);}
h1{font-size:64px;font-weight:900;padding:70px 90px 0}
</style></head><body>
<h1>服务器状态</h1>
<p style="padding:0 90px;color:#94a3b8">{{host}} · CPU {{cpu}}% · 进程 {{proc_total}}</p>
<p style="padding:16px 90px;font-size:22px">{{comment}}</p>
</body></html>
```

丢进 `styles/_favorites/极简.html`，`/状态卡 随机 极简` 就能出图。

### 跑不通怎么办

模型写的代码是在一个小沙箱里跑的：`import` 只放行 PIL / math / time / random / colorsys / itertools / datetime，
`while True`、`open`、`eval`、双下划线属性一律拒掉，别的内置函数（`hasattr` `callable` `type` `iter` 这些）都能用。

跑挂了会带着报错再让模型改一版；如果是**超时**（默认 300 秒没回），下一版会自动换成不放底稿的精简提示再试，
免得拿一样大的提示继续撞。两版都挂会把错误写到 `out/errors/`，文件名带时间和第几版。

## 五、日志

每次调用都会在 AstrBot 运行日志里留一行，格式统一带作者名：

```
[astrbot_plugin_server_card] [INFO] [main.py:561]: [状态卡·FULL] 某某(123456) 调用了 /状态卡
[astrbot_plugin_server_card] [INFO] [main.py:566]: [状态卡·FULL] 用代码风格 code_xxx.py 画完
[astrbot_plugin_server_card] [INFO] [main.py:568]: [状态卡·FULL] 出图 0.24s -> .../card_xxx.png
```

生成类的指令会多打方向、耗时：

```
[状态卡·FULL] 小明(123456) 调用了 /状态卡重做风格 · 抽到方向：故障艺术，错位色带，撕裂文字
[状态卡·FULL] 第 1 版跑通 · 采集 0.7s · 模型 5.0s · 总 10.2s
```

跑挂的时候是 WARN，会写清第几版、卡了多久、错在哪：

```
[状态卡·FULL] 第 1 版没跑通（已用 6.3s）: 不许 import os
```

├── freedraw.py          自由代码的安全执行（AST 检查 + builtins 白名单）

出图时的采样顺序：`collect()` 拿数据 → 有 `code_file` 就跑代码，没有就 `render()` 画 JSON 样式 → 存 `out/` → 发群 → 删文件。

## 八、常见问题

**改了风格没变化？**
看配置里 `code_file` 是不是填了东西，填了就走代码，`style_name` 不生效。

**重做风格一直失败？**
模型写出来的代码过不了检查或跑不通。插件会自动把报错回喂给模型再写一版，两版都不行就放弃，日志里有具体原因。多半是它想 `import os` 或者画出了画布边界。

**出图很慢？**
只有生成新风格才慢，要等模型写代码。日常群友要图（`code_file` 填 `random`）是直接跑已有代码，0.2 秒。

**AI 点评没了？**
`comment_mode` 是不是 `off`，`show_comment` 是不是关了，或者模型那条挂了——挂了不影响出图，日志里有 WARN。

**选了 HTML 渲染器，代码风格怎么不生效了？**
`.py` 是 PIL 语法，浏览器跑不了，会自动退回 PIL 出图。想在这种模式下玩排版，就写 `.html` 模板。

**HTML 渲染报找不到浏览器？**
装个 Edge 或 Chrome 就行，Windows 一般自带 Edge。路径是写死的那几个常见位置，绿色版或者装在别处的找不到。

**收藏夹里的文件会不会被插件删掉？**
不会。备份轮换和存档清理都只扫 `styles/` 根目录，收藏夹是独立目录，插件读它之前先建目录，从来不往外删东西。

**随机抽不到我放进去的文件？**
只认 `.py` 和 `.json`，别的后缀会被忽略；文件名别以点开头。抽不到时指令会回一条消息，把它现在认得的模板名都列出来，对一下就知道是名字写错了还是没放进去。

**素材里明明有图，为什么没用上？**
先确认素材文件夹配得对，再看日志里那行「挑图完成 · 挑了 N 张」。0 张就是模型觉得不合适，名字对不上也会这样——清单里带子文件夹，是 `人物甲/xxx.jpg` 这种写法。

**为什么一次贴了三张图？**
之前没有上限，模型爱凑数。现在它只在你点名要好几样、或者一张撑不起版面时才多挑，顶天三张。

**出图怎么越来越慢了？**
看看是不是规划、挑图、画图三步都用了大模型。挑图换成小模型能省一截，规划也不吃能力。

**能商用吗？**
MIT，随便用。

## 九、写在最后

### 给关心这个项目的人

这插件不是什么商业项目，就是一个人嫌 AstrBot 自带的图太丑，一路骂着让 AI 改出来的东西。所以它的每一版都很粗糙，也每一版都真的能用。

如果你也在用，记住三件事。

第一，觉得不好看就直接说，别客气。这个项目从 0.5 到现在每一版都是被骂出来的，模棱两可的反馈在这里没用，"底下空一块""字太小了看不清"这种才管用。

第二，模板是消耗品。删了就删了，重出就是了，不要抢救某一版。真喜欢就丢进收藏夹，插件从来不删收藏夹里的东西。

第三，别指望它开箱就符合你的审美。它的价值在于能用一句话描述出你脑子里那张图，而不是替你审美。

### 给其他智能体

如果你也是被叫来改这个仓库的 AI，下面几条是我踩出来的，拿走不谢。

**用户说的"固定"，通常是"这一次别动"，不是"永远写死"。** 我把一句"出图那一刻就固定"理解成硬编码一个文件名，结果下一张卡莫名其妙顶着别人的脸。多问一句"是这张卡固定，还是这一版固定"，能省一小时。

**能写进代码的规则，别交给提示词。** 提示词里的"不许"会被忽略，代码里的 `return None` 不会。柱状图第一名永远 100% 这个 bug 反复出现，就是因为真正该改的是字段语义，而我一直在提示词里求模型别用那个字段。

**别用正则遮丑。** 立绘空了就把 `src` 删掉，看起来图是好的，实际上空位还在。问题在哪层，就在哪层修，藏起来的东西迟早会回来找你。

**提示词越像法典，模型越容易走偏。** 一屏的硬性要求里，模型只能记住最后三条。想让它别乱塞图，不如把"挑不到就交空数组"这一条写得像命令。

**跑一遍，别猜。** 改完代码看看它到底渲染出什么。我这次光靠"读代码觉得没问题"，把坏模板交出去三次。

**用户的截图里问题往往不止一个。** 他说颜色不对，图里可能还有文字重叠和裁切。一次指出来，别挤牙膏。

最后一句：这插件里所有看起来"莫名其妙"的设计，背后都有一次具体的争吵。改之前先看看它为什么在那儿。
